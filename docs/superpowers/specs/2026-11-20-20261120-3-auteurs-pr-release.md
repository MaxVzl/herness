# Auteurs dans la PR de release

## Intention

Depuis la PR #14, le workflow `release-please.yml` ajoute `by @auteur` à chaque entrée des notes d'une release **une fois celle-ci créée**. La description de la PR de release ouverte par release-please, elle, ne nomme personne. On veut voir les auteurs dès cette PR, avant de la merger.

Au passage, on corrige un trou de l'existant : l'auteur n'est cherché que par le `[#N]` de la ligne. Or les entrées issues de commits de merge, sans `(#N)` dans leur titre, n'en ont pas (releases 0.7.0 et 0.8.0) et restent sans auteur.

## Constat

- release-please réécrit la description de sa PR à chaque push sur `main` : l'ajout des auteurs doit être refait à chaque passage, après release-please.
- Au merge, release-please construit les notes de release **à partir de la description de la PR** : les `by @auteur` déjà présents y passent tels quels. L'étape qui annote la release doit donc ignorer une ligne déjà annotée, sinon l'auteur apparaît deux fois.
- La PR de release ouverte porte le label `autorelease: pending` (puis `autorelease: tagged` après la release).
- Chaque entrée contient le lien de son commit (`…/commit/<sha de 40 caractères>`). L'API GitHub `repos/<dépôt>/commits/<sha>/pulls` renvoie la PR qui a apporté ce commit (vérifié : `MaxVzl` pour les deux entrées de la 0.8.0).

## Objectifs

- La description de la PR de release ouverte affiche `by @auteur` au bout de chaque entrée dont l'auteur est trouvé. Elle est remise à jour à chaque push sur `main`.
- Les notes de release gardent leurs auteurs, sans doublon.
- Pour une entrée sans `[#N]`, ou dont le `#N` ne donne pas d'auteur, l'auteur est cherché par le commit de l'entrée.

## Non-objectifs

- Réécrire les notes des releases déjà publiées (0.7.0, 0.8.0…).
- Toucher au `CHANGELOG.md` : il est commité dans la branche de release-please et reste sans auteurs.
- Changer la configuration de release-please.

## Anti-objectifs

- Faire échouer le workflow de release parce qu'un auteur est introuvable ou qu'un appel à `gh` échoue : la ligne reste alors telle quelle.
- Modifier autre chose que la fin des lignes d'entrées : l'en-tête et le pied de la PR, ainsi que les titres, doivent rester intacts pour que release-please continue de relire la description au merge.

## Approches envisagées

- **A. Script shell dédié et testé (retenue).** `.github/scripts/auteurs-notes.sh` lit des notes sur l'entrée standard et les renvoie annotées. Le workflow l'appelle pour la PR et pour la release. Le script est testé avec vitest et un faux `gh`, comme `install.sh`. C'est léger, sans dépendance, et la logique n'existe qu'en un seul exemplaire.
- B. Même script en TypeScript : plus cohérent avec le projet, mais il faudrait installer Node et pnpm dans le job de release à chaque push. Écartée.
- C. Logique dupliquée dans le YAML : rapide, mais en deux exemplaires et sans test. C'est ce qui a laissé passer le trou des releases 0.7.0 et 0.8.0. Écartée.

## Conception

### Le script `.github/scripts/auteurs-notes.sh`

- Usage : `auteurs-notes.sh <propriétaire/dépôt>`, notes sur l'entrée standard, notes annotées sur la sortie standard. Le script est exécutable (bit `x` commité).
- Pour chaque ligne :
  1. Si elle se termine déjà par ` by @<login>` : inchangée.
  2. Sinon, si elle contient `[#N]` (le premier) : auteur = `gh pr view N --repo <dépôt> --json author --jq .author.login`.
  3. Si l'auteur est toujours vide et que la ligne contient `/commit/<sha de 40 caractères hexadécimaux>` (le premier) : auteur = `gh api repos/<dépôt>/commits/<sha>/pulls --jq '.[0].user.login // empty'`.
  4. Si l'auteur est vide, contient `bot` ou commence par `app/` : ligne inchangée. Sinon : la ligne suivie de ` by @<auteur>`.
- Un échec de `gh` vaut un auteur vide. Le script ne s'arrête jamais en erreur pour ça.
- Toutes les autres lignes, lignes vides comprises, sont recopiées à l'identique.

### Le workflow `.github/workflows/release-please.yml`

- `actions/checkout@v4` s'exécute à chaque passage, plus seulement à la création d'une release, puisque le script vit dans le dépôt.
- L'étape « Auteurs des PR dans les notes de release » garde sa condition et appelle le script au lieu de la boucle en ligne.
- Une nouvelle étape « Auteurs des PR dans la PR de release », sans condition, placée en dernier :
  - elle cherche la PR ouverte qui porte le label `autorelease: pending` et s'arrête sans erreur s'il n'y en a pas ;
  - elle passe la description de cette PR dans le script ;
  - elle ne lance `gh pr edit --body-file` que si la description a changé.

Les permissions actuelles (`contents: write`, `pull-requests: write`) suffisent.

### Tests

- `test/ci/auteurs-notes.test.ts` (vitest) lance le script avec un faux `gh` placé en tête du `PATH`. Il couvre : l'auteur trouvé par `#N`, l'auteur trouvé par le commit, le repli sur le commit quand le `#N` ne donne rien, une ligne déjà annotée, un bot, un échec de `gh`, et les lignes sans lien.
- `test/ci/release-workflow.test.ts` vérifie, par lecture du texte du workflow, que le script est appelé pour la release et pour la PR, que le checkout n'est plus conditionnel et que l'ancienne boucle en ligne a disparu.

## Laissé à l'implémenteur

Le détail du faux `gh` et la manière d'extraire `#N` et le sha en shell.
